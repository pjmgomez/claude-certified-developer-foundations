Phase 5 · Agents & Workflows

Workflow vs agent

The most important architecture decision — and why the answer is usually “keep it simple.”

Domain 1.1 · Agent Architecture Domain 1 = 14.7%

“Agent” is the exciting word, but most production value comes from workflows. Knowing which to reach for — and defaulting to the simpler one — is the single most valuable lesson from Anthropic’s “Building Effective Agents.”

Your win: classify three tasks as workflow or agent, and justify each in one sentence.

Read alongside The workflow-patterns sheet. Foundation: Building Effective Agents.

The distinction

  • Workflow — LLMs and tools orchestrated through predefined code paths. Predictable, testable, cheap. Right when the steps are known.
  • Agent — the model dynamically directs its own process and tool use. Flexible but costlier and less predictable. Right when you can’t hardcode the path.
  • Augmented LLM — the building block under both: a model plus retrieval, tools, and memory.
The rule to internalise Find the simplest solution possible, and only add complexity when it demonstrably improves outcomes. Reach for an agent only for open-ended problems where the path can’t be predicted and you can trust the model’s decisions in a guarded environment. Three principles when you do: simplicity, transparency (show the plan), and a well-crafted agent–computer interface (tool docs you test like prompts).
