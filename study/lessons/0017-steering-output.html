Steering output

Prefill the answer, constrain the shape, and never trust untrusted input.

Domain 6.2 · Prompt Engineering

Beyond structure, a few techniques steer what comes out: prefilling the assistant turn, stating output constraints, and sanitising anything that came from outside your system.

Your win: prefill Claude’s reply to force a format, and know when prefilling is the wrong tool.

The techniques

  • Prefilling. Seed the start of the assistant turn to bias the shape — e.g. an opening { to push toward JSON, or "Sure, here are three:" to set tone.
  • Output constraints. Say exactly what you want: “Answer with only the ticker symbol,” “At most 40 words,” “No preamble.”
  • Input sanitisation. Treat text from users, tools, or documents as data, not instructions. Wrap it in XML and never concatenate it into your instruction block (full treatment in Phase 7).

Do it

  1. Prefill to force JSON without asking for it in prose: 
    resp = client.messages.create(
    model="claude-sonnet-5", max_tokens=200,
    messages=[
        {"role": "user", "content": "Give me a user object for Ada Lovelace."},
        {"role": "assistant", "content": "{"},   # prefill: the reply must continue the JSON
    ],
)
print("{" + resp.content[0].text)                 # you own the opening brace
  2. Add a hard constraint to the user turn (“Keys: name, born. Numbers only for born.”) and confirm the shape tightens.
Prefilling vs. structured outputs Prefilling biases the format; it doesn’t guarantee it — and it is incompatible with JSON structured outputs (next lesson), which do guarantee it. Use prefilling for tone and light nudges; use structured outputs when you need a hard guarantee. On some newest models, prefilling with thinking disabled can surface internal XML tags — verify per model.

Check yourself

Ask your teacher Want to see prefilling and structured outputs solve the same task, side by side? Ask — the contrast makes the tradeoff stick.
