Phase 7 · Security & Safety

Data leakage & PII

Minimize what you send, watch what comes back, and keep sensitive data out of schemas.

Domain 7.1 · AI Application Security

Every token you send is data you’re trusting to a pipeline; every token that returns is data that could leak. Handling personal and sensitive information well is both a security and a compliance concern.

Your win: apply data minimization, and place PHI correctly when using structured outputs.

The practices

  • Minimize PII in prompts. Send the least sensitive data that accomplishes the task; redact or tokenize where you can.
  • Watch the output. Monitor responses for leaked secrets, system-prompt disclosure, or PII the model shouldn’t have surfaced.
  • Structured outputs & PHI. Structured outputs are HIPAA-eligible, but PHI must not appear in the schema definition — schemas are compiled and cached separately from the request.
  • AAA / CIA. Enforce authentication, authorization, confidentiality, privacy, and integrity at every boundary — not just the front door.
The schema trap It’s tempting to bake an example value into a schema ("patient": "Jane Doe, DOB..."). Don’t — the schema is cached separately, so real PHI in a schema definition outlives the request it belonged to. Keep sensitive values in the message, never the schema.
