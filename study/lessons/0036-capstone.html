Phase 8 · Capstone & Readiness

Capstone: build & operate one app

The exam guide’s own advice — build and run a real Claude application.

Domains 2 · 4 · 6 · 7 · 8 Ties the whole course together

Everything so far has been one concept at a time. The capstone fuses them into a single working app — a support-triage assistant that caches, calls a guarded tool, produces structured output, streams a reply, and reports its own token cost. If you can build and explain this, you can pass.

Your win: run capstone.py, watch a cache hit on the rerun, and defeat an injection attempt against the tool guard.

What it exercises

Course conceptWhere it appears
Prompt caching (Phase 3)cache_control on the big system policy block.
Tool-use loop (Phase 2)lookup_order tool, stop_reason: tool_use, matched tool_results.
Guardrail (Phase 7)guard_tool_call() — a PreToolUse-style deny before executing.
Structured output (Phase 4)A forced triage_summary tool with enum’d fields.
Streaming (Phase 1)The customer reply streamed via messages.stream.
Evaluation (Phase 5.4)usage printed — input/output/cache-read tokens.

Do it

  1. Run it. With your key set: python study/capstone/capstone.py. Confirm you get a structured summary, a usage line, and a streamed reply.
  2. Prove the cache. Run it again within ~5 minutes and watch cache_read jump from 0 to the size of the policy block — the Phase 3 lesson, live.
  3. Attack the guard. Change the opening message to ask about order ORD-../../etc/passwd. Confirm guard_tool_call() denies it before it executes — the Phase 7 lesson, live.
  4. Extend it (optional). Swap the forced-tool summary for output_config.format; move the guard into a real Agent SDK PreToolUse hook; add a Haiku pre-screen on the inbound message.
This is the readiness bar The exam guide literally recommends building “at least one Claude application that exercises the API, integrates one or more tools, applies basic prompt and context engineering, and includes simple security and evaluation practices.” This capstone is that app. Operating it — not just reading it — is the goal.

Check yourself

Ask your teacher Once it runs, bring me the usage output and we’ll reason about its cost — then pick one extension to build together.
