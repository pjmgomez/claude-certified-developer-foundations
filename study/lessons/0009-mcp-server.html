Phase 2 · Tools & MCP

Build an MCP server

Package a tool, a resource, and a prompt once — and any client can use them.

Domain 8.2 · MCP Server Development Domain 8.3 · Agentic Customization

Custom tools live inside one app. The Model Context Protocol lets you expose the same capability as a standalone server that many clients connect to — Claude Code, Claude Desktop, your own SDK app. It’s an open JSON-RPC protocol with three primitives: Tools, Resources, Prompts.

Your win: a running stdio MCP server exposing one of each primitive, poked live in the MCP Inspector — no Anthropic key required.

Read alongside The MCP essentials sheet — primitives, transports (stdio vs Streamable HTTP), lifecycle, and the CLI.

Do it

  1. Install the SDK with its CLI: 
    pip install "mcp[cli]"
  2. Write server.py: 
    from mcp.server.mcpserver import MCPServer   # this class was formerly called FastMCP

mcp = MCPServer("inventory")

@mcp.tool()
def stock_level(sku: str) -> int:
    """Units in stock for a SKU."""
    return {"A1": 12, "B2": 0}.get(sku, 0)

@mcp.resource("inventory://skus")
def all_skus() -> str:
    """Every known SKU, one per line."""
    return "A1\nB2"

@mcp.prompt()
def restock_note(sku: str) -> str:
    """Draft a restock request."""
    return f"Write a short restock request for SKU {sku}."

if __name__ == "__main__":
    mcp.run()        # stdio by default
  3. Explore it live in the Inspector: 
    mcp dev server.py
    List the tool, call stock_level("A1"), read the inventory://skus resource, and render the prompt.
  4. To use it from Claude Code, register it with claude mcp add (confirm the exact flags in the Claude Code docs). The same server, now available to a real agent.
Trust boundary The stdio transport is not sandboxed — a local server runs with your privileges. Only run servers you trust, and require explicit user consent before a client calls their tools.
