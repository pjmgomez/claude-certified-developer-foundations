Agent frameworks

Strands, LangGraph, PydanticAI — and why Anthropic says start without one.

Domain 1.3 · Frameworks

Frameworks can speed you up — and hide the prompts and responses you need to see when things break. Know what each is for, and know Anthropic’s stance: start with the API directly; adopt a framework only once you understand the code underneath it.

Your win: match each framework to the job it’s best at.

FrameworkShapeBest for
Claude Agent SDK Claude Code’s loop as a library. Claude-native agents with tools, hooks, subagents (Lessons 0023–0024).
Strands (AWS) Model-driven loop; OpenTelemetry. AWS-centric deployment (Bedrock AgentCore, Lambda, Fargate); runs inside Amazon Q, Kiro, Glue.
LangGraph Graph: nodes = steps, edges = control flow. Stateful, long-running, multi-actor flows with cycles, persistence, durable execution, and human-in-the-loop checkpoints. Observability via LangSmith.
PydanticAI Type-safe Python agents. Runtime output validation with auto-retry on malformed responses; strong testing (TestModel, FunctionModel, Agent.override, pytest); built-in usage limits. Observability via Logfire.
Anthropic’s guidance Start with the API directly. If you adopt a framework, understand the code it generates — abstraction layers obscure the actual prompts and responses, which makes debugging harder. A framework you can’t see through is a liability when an agent misbehaves.
