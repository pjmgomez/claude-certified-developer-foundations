Domain 7.4 · Identity, Secrets & Key Management

The whole system’s security often reduces to one bearer credential. Handle the API key like the money it can spend, and put identity and access controls around every path that reaches the model.

Your win: a key-handling checklist you’d actually pass a security review.

Keys

  • Pass the key in the x-api-key header; store it in environment variables or a secrets manager — never in code or a committed file.
  • Rotate keys; a bad/revoked key is a 401 authentication_error. Keep separate dev and prod keys, and scope by workspace.

Identity & access

  • On Bedrock / Vertex, use IAM roles (AWS SigV4 on Bedrock) instead of a raw Anthropic key.
  • Validate identity, verify access level, and monitor authorized access via audit logs.
  • Least privilege for tools — pre-approve safe tools (allowed_tools), deny dangerous ones, and require approval for risky actions (ties back to hooks).
The one that ends careers A key committed to git — even in history, even in a private repo — is compromised. Use the environment or a secrets manager, add pre-commit secret scanning, and rotate immediately if one leaks.
