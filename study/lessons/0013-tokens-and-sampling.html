Tokens, sampling & non-determinism

The raw materials: what you pay for, what “the context window” really is, and why the same prompt wanders.

Domain 5.1 · LLM Fundamentals

Under every call are a few fundamentals worth making concrete: tokens (the billed unit), the context window (the model’s working memory), sampling controls (how random the next token is), and the fact that Claude is never perfectly deterministic.

Your win: count the tokens in a prompt before sending it, and feel temperature change the output.

The fundamentals

  • Token — a chunk of text (roughly a word-piece). You pay per input and output token; output runs ~5× the input rate.
  • Context window — everything the model can reference at once, including its own output. Its working memory (200K on Haiku 4.5, up to 1M on the 5-series).
  • Sampling — temperature (0–1; near 0 = focused/analytical, near 1 = creative), plus top_p (nucleus) and top_k. Tune temperature or top_p, not both at once.
  • Non-determinism — even at temperature=0 the output is not guaranteed identical across calls. Low temperature is reproducible enough to often replay a bad call, not a guarantee.
  • Prompting shots — zero-shot (instruction only), single-shot (one example), multi-shot / few-shot (several).

Do it

  1. Count tokens before you spend them: 
    n = client.messages.count_tokens(
    model="claude-sonnet-5",
    messages=[{"role": "user", "content": "How many tokens is this sentence?"}],
)
print(n.input_tokens)
  2. Run the same creative prompt at temperature=0 then temperature=1, a few times each. Note how 0 barely moves and 1 wanders — and that even 0 isn’t byte-identical.
