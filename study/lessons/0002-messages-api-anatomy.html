Phase 1 · Core API Mechanics

The shape of a Message

What you send, what comes back, and why the conversation lives in your code.

Domain 2.3 · API Mechanics Domain 2 = 33% of the exam

In Phase 0 you made one call. Now name its parts. A request has a few core fields; the response is a Message object with a predictable structure. Master this and streaming, tools, and agents are all just richer content flowing through the same envelope.

Your win: a two-turn conversation you drive yourself, with a system prompt, where you read stop_reason and inspect the content blocks.

The request

FieldRole
modelWhich model answers. Required.
messagesThe conversation so far: a list of {role, content}, alternating user / assistant. Required.
max_tokensHard cap on output length. Required.
systemTop-level role / instructions (a string, not a message).
temperature, top_p, top_kSampling controls (tune one, not several at once).
stop_sequencesStrings that force the model to stop.

The response

A Message carries id, role, model, content (a list of typed blocks, e.g. {"type":"text","text":"..."}), usage, and stop_reason — one of end_turn, max_tokens, tool_use, stop_sequence, or refusal.

The API is stateless Claude remembers nothing between calls. To continue a conversation you resend the prior turns in messages — the “memory” is a list you maintain. There is no server-side session id.

Do it

  1. Extend your hello.py into a two-turn chat: 
    import anthropic

client = anthropic.Anthropic()
MODEL = "claude-sonnet-5"   # verify on the models page
SYS = "You are a terse tutor. Answer in one short sentence."

first = client.messages.create(
    model=MODEL, max_tokens=300, system=SYS,
    messages=[{"role": "user", "content": "What is a content block?"}],
)
print("A:", first.content[0].text, "|", first.stop_reason)

second = client.messages.create(
    model=MODEL, max_tokens=300, system=SYS,
    messages=[
        {"role": "user", "content": "What is a content block?"},
        {"role": first.role, "content": first.content},  # replay the whole assistant turn
        {"role": "user", "content": "Give one example."},
    ],
)
print("A:", second.content[0].text)
  2. Run it. Notice the second answer only makes sense because you resent the first exchange.
  3. Delete the replayed assistant turn and rerun. Watch the follow-up lose the thread — proof the state lived in your messages list, not on the server.
  4. Print first.content[0].type and first.usage to see the block type and token cost.

Check yourself

Ask your teacher Unsure why the assistant turn gets replayed as content objects rather than a string? That is exactly the kind of thing to ask me — it pays off when we reach tool use.
