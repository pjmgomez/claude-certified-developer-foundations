Phase 2 · Tools & MCP

Choosing your mechanism

Built-in tool, custom tool, Skill, or MCP? Pick by reuse, ownership, and context cost.

Domain 8.3 · Agentic Customization 4.1% of the exam

You now have four ways to extend Claude. Picking the wrong one is a common design mistake — hard-coding logic that should be an MCP server, or reaching for MCP when a Skill would do. Choose by three questions: who reuses it, who maintains it, and what it costs your context.

MechanismBest forWatch out
Built-in tools
web_search, code_execution…		 Common actions you don’t want to build or maintain. Fastest path. They don’t reach your internal systems.
Custom tools Your own API or logic, called from one app, where you control execution. Not automatically reusable across other apps.
Agent Skills Procedural know-how / workflows. Progressive disclosure — only name+description sit in context until triggered. Knowledge and process, not a live connection to a system.
MCP servers A capability reused across many clients/agents and maintained independently. Tool descriptions consume context constantly (no progressive disclosure) — size the set.
The exam’s favourite distinction “Reusable across several apps, maintained independently” → MCP server. Hard-coding into each prompt isn’t reusable; pasting data gives no live access; built-in tools don’t reach arbitrary internal APIs. (That’s the reasoning behind the guide’s sample Q3.)
