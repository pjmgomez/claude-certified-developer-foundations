The deterministic layer — block the destructive tool call before it runs.

Domain 7.3 · Claude Hooks

Prompts persuade; hooks enforce. A PreToolUse hook runs your code before any tool executes and can veto it — the right home for “never run rm -rf” and other hard stops. Crucially, a hook deny outranks even permission-bypass modes.

Your win: write a PreToolUse hook that blocks a destructive command, and know why it holds even under --dangerously-skip-permissions.

Read alongside The hooks sheet: events, the exit-code shell form, the SDK callback form, and the precedence rule.

Do it

  1. Register a PreToolUse guard on the agent loop (SDK form): 
    from claude_agent_sdk import ClaudeAgentOptions, ClaudeSDKClient, HookMatcher

async def block_destructive(input_data, tool_use_id, context):
    if input_data.get("tool_name") == "Bash":
        cmd = input_data.get("tool_input", {}).get("command", "")
        if "rm -rf" in cmd:
            return {"hookSpecificOutput": {
                "hookEventName": "PreToolUse",
                "permissionDecision": "deny",
                "permissionDecisionReason": "Blocked: destructive rm -rf."}}
    return {}                                  # {} = allow

options = ClaudeAgentOptions(
    allowed_tools=["Bash"],
    hooks={"PreToolUse": [HookMatcher(matcher="Bash", hooks=[block_destructive])]})
  2. Ask the agent to rm -rf something and confirm the call is denied before it runs. Try a safe echo and confirm it passes.
  3. Note the shell form (settings.json): the same guard as a command that exits 2 to deny (0 allows, 1 warns) — matcher regex like Bash or Write|Edit.
Deny outranks bypass A PreToolUse deny is evaluated before permission-mode checks, so it blocks the tool even under bypassPermissions / --dangerously-skip-permissions. That’s what makes it the right place for hard safety stops. (PermissionRequest hooks, by contrast, don’t fire in headless mode.)
