Domain 7.2 · Guardrails & Safe Deployment

One guardrail is a single point of failure. Safe deployment stacks independent controls — a prompt guard, a classifier, and deterministic code — so a miss at one layer is caught at the next, all on top of a least-privilege design.

Your win: lay out a three-layer guardrail stack and spot why a prompt-only guard is weak.

Read alongside The security sheet (guardrail layering + secure-by-design).

The layers

  • Prompt-level guard — instructions that set boundaries. Cheap, but shares the same computational substrate as the threat, so it can be talked around.
  • Classifier / LLM-as-judge — a separate model that screens input or output (Llama Guard, ShieldGemma, PromptGuard, NeMo Guardrails). Independent of the main model’s reasoning.
  • Deterministic controls — code that can’t be argued with: allowlists, schema validation, and hooks (next lesson).

Secure-by-design

  • Least privilege — pre-approve only the tools a task needs; deny the rest. An agent that can’t reach a dangerous tool can’t be tricked into using it.
  • Egress allowlists — restrict outbound network access to limit exfiltration. Even allowlisted endpoints can be abused, so pair with output filtering.
  • IAM & privacy — identity and access management, data minimization, and the content policy (Anthropic Usage Policy) as the floor.
Why prompt guards alone fail A prompt guardrail is reasoning trying to police reasoning — the same substrate the attacker targets. It belongs in the stack, but never as the only layer. Put the hard stops in deterministic code.
