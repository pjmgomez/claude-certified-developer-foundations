Context engineering

Context is a budget, not a bucket. Spend it on signal.

Domain 6.1 · Context Engineering Domain 1 · Subagents

Long-running agents fail less from bad reasoning than from context rot — windows stuffed with stale tool dumps and detail. The discipline: treat context as a finite budget and keep it to the smallest set of high-signal tokens.

Your win: take a fat tool output and make it lean, and know when to hand work to a subagent.

The moves

  • Prune tool outputs. Return only what the model needs — paginate, filter, range-select, set sensible defaults. A tool that returns 5,000 rows when 5 will do is a context leak. (Claude Code truncates tool responses at ~25,000 tokens by default.)
  • Steer toward token-efficient strategies. Many small, targeted searches usually beat one giant dump the model must then wade through.
  • Isolate with subagents. Give a sub-task its own context window; return only the distilled result to the parent. The parent never sees the mess.

Do it

  1. Find a tool in your Phase 2 loop that returns a big blob. Add pagination and field selection so it returns, say, the top 5 rows and only the columns asked for.
  2. Re-run a multi-step task and watch usage.input_tokens on later turns. Leaner tool results = a smaller, sharper window = better answers for longer.
  3. Sketch where a subagent would help: a research or search sub-task whose 20 intermediate steps the parent should never carry — just its one-paragraph conclusion.
The principle to carry Every token you add competes for the model’s attention. More context is not more capability past a point — curate ruthlessly. The next lesson automates this with context editing, compaction, and memory.

Check yourself
