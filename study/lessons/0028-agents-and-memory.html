Phase 6 · Claude Code

Agents & Agent Memory

Delegate to subagents, let Claude keep its own notes, and run without a terminal.

Domain 3 · Claude Code Operation

Three Claude Code features round out the picture: subagents (delegation with isolation), Agent Memory (notes Claude writes for itself), and headless mode (Claude Code in CI and cron). Note the two kinds of memory: you write CLAUDE.md; Claude writes Agent Memory.

Your win: tell CLAUDE.md apart from Agent Memory, and run Claude Code headless in a script.

Read alongside The files sheet (Agents, Agent Memory) and the config sheet (headless / streaming).

The three features

  • Subagents — markdown in .claude/agents/ with YAML frontmatter (name, description, optional model + tool access). Each runs in its own fresh context; only the final message returns. Built-ins: Explore, Plan, general-purpose. They don’t inherit skills unless listed.
  • Agent Memory — learnings Claude writes under ~/.claude/projects/<project>/memory/ with a MEMORY.md entrypoint. The first 200 lines (or 25KB) of MEMORY.md load at the start of every conversation; topic files load on demand. Toggle with /memory or CLAUDE_CODE_DISABLE_AUTO_MEMORY=1.
  • Sessions & modes — --continue/--resume to pick up where you left off; headless -p for automation.

Do it

  1. Run Claude Code headless from a script — no TTY, reuses your settings, hooks, and permissions: 
    claude -p "Summarize today's git changes in three bullets"
    This is what powers pre-commit hooks, cron jobs, and GitHub Actions.
  2. Add --output-format stream-json to consume the run programmatically.
  3. Open ~/.claude/projects/<project>/memory/MEMORY.md after a few sessions and read what Claude chose to remember — then contrast it with your hand-written CLAUDE.md.
Headless gotcha PermissionRequest hooks do not fire in headless mode. A permissionDecision: "defer" pauses a call so a wrapping process can decide — design automation with that in mind.
