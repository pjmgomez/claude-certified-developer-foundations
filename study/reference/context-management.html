Context management

Keep the window a small set of high-signal tokens as a conversation grows.

Domain 6.1 · Context Engineering

Context is a finite resource; the goal is the smallest set of high-signal tokens. Four levers, cheapest first:

LeverWhat it does
Prune tool outputsPaginate / filter / range-select so a tool returns only what’s needed. (Claude Code caps tool responses at ~25,000 tokens by default.)
Context editingServer clears old tool results / thinking once a threshold trips.
CompactionServer summarises older context into a compaction block.
Memory + subagentsPersist facts to files; isolate work in subagents with their own windows.

Context editing and compaction live under one config, behind the beta header context-management-2025-06-27:

context_management = {"edits": [
    {"type": "clear_tool_uses_20250919",           # clear old tool results
     "trigger":  {"type": "input_tokens", "value": 30000},
     "keep":     {"type": "tool_uses",    "value": 3},
     "clear_at_least": {"type": "input_tokens", "value": 5000},
     "exclude_tools": ["memory"]},                 # never clear memory writes
]}
# server-side summarization instead of clearing:
#   {"type": "compact_20260112"}   # trigger defaults to 150000 input tokens

Applied edits come back on message.context_management.applied_edits (cleared_input_tokens, cleared_tool_uses).

Memory tool

A file-based CRUD memory (tool type memory_20250818) that persists across conversations under the /memories directory — commands view, create, str_replace, insert, delete, rename. Add memory to exclude_tools so context editing never wipes what it writes.

Why bother (reported) Anthropic reports combining the memory tool with context editing improved performance 39% over baseline (context editing alone: 29%), and in a 100-turn web-search eval, context editing cut token use 84%. Treat exact figures as indicative.
