Directing tools: tool_choice & tool types

Who decides when a tool runs, and where the tool actually executes.

Domain 8.1 · Tool Implementation
tool_choice — four options
ValueBehaviour
{"type":"auto"}Model decides whether to use tools. Default when tools is present. May call zero or more.
{"type":"any"}Model must use a tool, but picks which.
{"type":"tool","name":"x"}Force the named tool. Use this to guarantee structured output from one known tool.
{"type":"none"}No tools. Default when tools is absent.

auto, any, and tool accept disable_parallel_tool_use (default false). Set it true to force exactly one tool call.

Cache gotcha Changing tool_choice (or the tools array) between calls invalidates cached message blocks — it changes the tool preamble the cache is keyed on.

Parallel tool use

Claude 4+ models call tools in parallel by default: one assistant turn can contain multiple tool_use blocks. Execute them all, then return all the tool_result blocks in a single following user turn.

Client tools vs. server tools
Client toolsServer tools
Run in your application. You execute them and return a tool_result. Run on Anthropic infrastructure. Anthropic executes them; results come back inline.
Your custom tools; Anthropic-schema helpers you host, e.g. bash, text_editor. web_search, web_fetch, code_execution, memory, tool_search.
