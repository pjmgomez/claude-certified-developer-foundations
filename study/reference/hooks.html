Claude Code hooks

The deterministic “must-do” layer — run code at lifecycle events, block destructive ones.

Domain 7.3 · Claude Hooks

Hooks are shell commands / callbacks that fire at lifecycle events. In settings.json they nest three levels: event → matcher group → handler. Matchers support regex (e.g. Edit|Write).

Key events
EventUse
PreToolUseBefore a tool runs — can block. The place for destructive-action guardrails.
PostToolUseAfter success — auto-format / lint. Cannot undo.
UserPromptSubmitInject context or reject a prompt.
Stop / SubagentStopEnd of a turn / subagent.
PreCompact / SessionStart / NotificationLifecycle taps.
PermissionRequestGate a permission — does NOT fire in headless mode.

Blocking with PreToolUse

Shell form (settings.json): exit code 2 denies, 0 allows, 1 warns. A deny is evaluated before permission-mode checks, so it blocks even under bypassPermissions / --dangerously-skip-permissions.

SDK form (callback):

async def guard(input_data, tool_use_id, context):
    if input_data.get("tool_name") == "Bash":
        cmd = input_data.get("tool_input", {}).get("command", "")
        if "rm -rf" in cmd:
            return {"hookSpecificOutput": {
                "hookEventName": "PreToolUse",
                "permissionDecision": "deny",              # allow | deny | ask | defer
                "permissionDecisionReason": "Refusing destructive rm -rf."}}
    return {}                                              # {} = allow

options = ClaudeAgentOptions(
    allowed_tools=["Bash"],
    hooks={"PreToolUse": [HookMatcher(matcher="Bash", hooks=[guard])]})
Hooks vs CLAUDE.md Hooks are the deterministic “must-do” layer; CLAUDE.md is the “should-do” layer. For anything that must not happen, use a PreToolUse hook — not a polite prose rule.
