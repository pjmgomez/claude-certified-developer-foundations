CLAUDE.md hierarchy

Loaded broad → specific and concatenated (later files add to, don’t override):

TierLocation
Managed policy/etc/claude-code/CLAUDE.md (Linux), /Library/Application Support/ClaudeCode/CLAUDE.md (mac), C:\Program Files\ClaudeCode\CLAUDE.md (Win)
User~/.claude/CLAUDE.md
Project./CLAUDE.md or ./.claude/CLAUDE.md
Local (gitignored)./CLAUDE.local.md

Files at/above cwd load in full at launch; subdirectory files load on demand. Target < 200 lines. Import with @path (max depth 4 hops). /init generates a starter (and reads .cursor/rules/, .cursorrules, .github/copilot-instructions.md).

Rules — .claude/rules/

Markdown auto-loaded alongside CLAUDE.md (no import needed). Unscoped rules load at launch (same priority as .claude/CLAUDE.md); path-scoped rules use YAML frontmatter paths: globs and load only for matching files. User rules (~/.claude/rules/) load before project rules, so project wins.

Skills — .claude/skills/<name>/SKILL.md

YAML frontmatter (name + description) loads at startup (~50–100 tokens); the body loads only on invoke — progressive disclosure. Keep the body < ~500 lines. Commands merged into skills: .claude/commands/deploy.md and .claude/skills/deploy/SKILL.md both create /deploy.

Agents — .claude/agents/

Markdown + YAML frontmatter (name, description, optional model + tool access). Each runs in a fresh context window; only the final message returns. Built-ins: Explore, Plan, general-purpose. Nest up to 5 levels. Subagents don’t inherit skills unless listed.

Agent Memory (auto memory)

Claude-written learnings under ~/.claude/projects/<project>/memory/ with a MEMORY.md entrypoint. The first 200 lines of MEMORY.md (or first 25KB), whichever comes first, load at the start of every conversation; topic files load on demand. Toggle via /memory, autoMemoryEnabled, or CLAUDE_CODE_DISABLE_AUTO_MEMORY=1. Distinct from CLAUDE.md, which you write.
