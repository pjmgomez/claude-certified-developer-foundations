Workflow patterns

The five patterns from “Building Effective Agents,” plus when an agent earns its keep.

Domain 1.1 / 1.3 · Architecture & Patterns

The building block under all of it is the augmented LLM: a model enhanced with retrieval, tools, and memory.

Workflow vs. agent
WorkflowAgent
LLMs + tools orchestrated through predefined code paths. Predictable, consistent. The LLM dynamically directs its own process and tool use. Flexible, model-driven.
Best for well-defined tasks with known steps.Best for open-ended problems where you can’t hardcode the path.
The decision rule Find the simplest solution possible, and only increase complexity when it demonstrably improves outcomes. Often a single well-tuned LLM call with retrieval and a few examples is enough. Agents trade latency and cost for flexibility — earn it.
The five patterns
PatternWhat it is
Prompt chainingDecompose into fixed sequential steps; each call uses the prior output. Add programmatic gates between steps. Trades latency for accuracy.
RoutingClassify the input, then send it to a specialized follow-up (easy → Haiku, hard → Opus). Separation of concerns.
ParallelizationTwo flavours: sectioning (independent subtasks run in parallel) and voting (same task run several times for confidence / diversity).
Orchestrator–workersA central LLM dynamically breaks a task into subtasks, delegates to workers, and synthesizes. Unlike parallelization, the subtasks are not predefined.
Evaluator–optimizerOne LLM generates; another evaluates and gives feedback, in a loop. Best when clear eval criteria exist and iteration adds value.

Three principles for agents

  1. Simplicity — keep the design as simple as the task allows.
  2. Transparency — show the agent’s planning steps.
  3. Agent–Computer Interface (ACI) — craft tool documentation and test it as carefully as you craft prompts.
